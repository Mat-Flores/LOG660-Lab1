1.5 Mot de passe
Interprétation retenue : au moins cinq caractères, uniquement des lettres et chiffres.

ALTER TABLE Utilisateur ADD CONSTRAINT ck_mot_de_passe
CHECK (REGEXP_LIKE(motDePasse, '^[[:alnum:]]{5,}$'));

1.6 Âge minimum
Le trigger vérifie que l'utilisateur inscrit comme client a au moins 18 ans.

CREATE OR REPLACE TRIGGER trg_age_client
BEFORE INSERT OR UPDATE OF idUtilisateur ON Client
FOR EACH ROW
DECLARE
    v_naissance Utilisateur.dateNaissance%TYPE;
BEGIN
    SELECT dateNaissance INTO v_naissance
    FROM Utilisateur
    WHERE idUtilisateur = :NEW.idUtilisateur;

    IF v_naissance IS NULL
       OR TRUNC(v_naissance) > ADD_MONTHS(TRUNC(SYSDATE), -216) THEN
        RAISE_APPLICATION_ERROR(-20001, 'Le client doit avoir au moins 18 ans.');
    END IF;
END;
/

La même règle s'applique lorsqu'on corrige la date de naissance d'un client.

CREATE OR REPLACE TRIGGER trg_modification_naissance
BEFORE UPDATE OF dateNaissance ON Utilisateur
FOR EACH ROW
DECLARE
    v_client NUMBER;
BEGIN
    SELECT COUNT(*) INTO v_client
    FROM Client WHERE idUtilisateur = :OLD.idUtilisateur;

    IF v_client > 0 AND (
        :NEW.dateNaissance IS NULL
        OR TRUNC(:NEW.dateNaissance) > ADD_MONTHS(TRUNC(SYSDATE), -216)
    ) THEN
        RAISE_APPLICATION_ERROR(-20001, 'Le client doit avoir au moins 18 ans.');
    END IF;
END;
/

1.7 Expiration de la carte
La carte reste valide jusqu'à la fin du mois indiqué dans dateExpiration.

CREATE OR REPLACE TRIGGER trg_expiration_carte
BEFORE INSERT OR UPDATE OF dateExpiration ON CarteCredit
FOR EACH ROW
BEGIN
    IF :NEW.dateExpiration IS NULL
       OR TRUNC(:NEW.dateExpiration, 'MM') < TRUNC(SYSDATE, 'MM') THEN
        RAISE_APPLICATION_ERROR(-20002, 'Date d''expiration de carte invalide.');
    END IF;
END;
/

1.8 Caractéristiques des forfaits
NULL représente la durée illimitée du forfait A.

ALTER TABLE Forfait MODIFY (dureeMaxJours NULL);
ALTER TABLE Forfait ADD CONSTRAINT ck_forfait_valeurs
CHECK (
    (code = 'D' AND cout = 5 AND locationsMax = 1
     AND dureeMaxJours IS NOT NULL AND dureeMaxJours = 10)
    OR
    (code = 'I' AND cout = 10 AND locationsMax = 5
     AND dureeMaxJours IS NOT NULL AND dureeMaxJours = 30)
    OR
    (code = 'A' AND cout = 15 AND locationsMax = 10
     AND dureeMaxJours IS NULL)
);

4. CAS 4 — LOCATION

4.1 Références obligatoires
Chaque location doit référencer un client et une copie existants.

ALTER TABLE Location MODIFY (
    idUtilisateur NOT NULL, code_copie NOT NULL, dateLocation NOT NULL
);

-- Vérifier les clés étrangères de la tâche 2 :
-- FOREIGN KEY (idUtilisateur) REFERENCES Client(idUtilisateur)
-- FOREIGN KEY (code_copie) REFERENCES Copie(codeCopie)

4.2 Disponibilité et quota
Une copie ne peut avoir deux locations en cours ; le nombre de locations
non retournées d'un client ne peut dépasser locationsMax.

CREATE OR REPLACE TRIGGER trg_verification_locations
AFTER INSERT OR UPDATE ON Location
DECLARE
    v_nombre NUMBER;
    v_max Forfait.locationsMax%TYPE;
BEGIN
    FOR cp IN (
        SELECT codeCopie FROM Copie ORDER BY codeCopie FOR UPDATE
    ) LOOP
        SELECT COUNT(*) INTO v_nombre
        FROM Location
        WHERE code_copie = cp.codeCopie AND dateRetour IS NULL;

        IF v_nombre > 1 THEN
            RAISE_APPLICATION_ERROR(-20003, 'Cette copie est deja louee.');
        END IF;
    END LOOP;

    FOR cl IN (
        SELECT idUtilisateur, code_forfait
        FROM Client ORDER BY idUtilisateur FOR UPDATE
    ) LOOP
        SELECT locationsMax INTO v_max
        FROM Forfait WHERE code = cl.code_forfait;

        SELECT COUNT(*) INTO v_nombre
        FROM Location
        WHERE idUtilisateur = cl.idUtilisateur AND dateRetour IS NULL;

        IF v_nombre > v_max THEN
            RAISE_APPLICATION_ERROR(-20004, 'Quota de locations depasse.');
        END IF;
    END LOOP;
END;
/

Le contrôle s'effectue après l'instruction pour pouvoir lire Location.
Cette version simple verrouille et vérifie toutes les copies et tous les clients.

4.3 Durée maximale
La date limite est dateLocation + dureeMaxJours : 10 jours pour D,
30 jours pour I et aucune limite pour A. Un retour tardif reste enregistrable ;
le dépassement sert à identifier les retards prévus dans la mise en situation.

5. PROCÉDURES À PRÉVOIR AU LABORATOIRE 2

p_ajouterClient
Entrées : nom, prénom, courriel, téléphone, naissance, mot de passe,
adresse complète, informations de carte et code du forfait.
Traitement : générer idUtilisateur et créer Utilisateur, Adresse,
CarteCredit et Client dans une même transaction, sans inscription partielle.

p_louerFilm
Entrées : identifiant du client connecté et identifiant du film choisi.
Traitement : attribuer une copie disponible et créer la location en générant
idLocation en interne. Une copie est disponible si elle n'a aucune location
dont dateRetour est NULL.

Les identifiants des nouveaux enregistrements ne sont pas des paramètres d'entrée.
Les erreurs doivent produire un message compréhensible pour le client.
Les procédures seront implémentées et testées au laboratoire 2 seulement.
